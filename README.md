# نظام إدارة المخاطر التشغيلية

نظام Laravel كامل باللغة العربية (RTL) لإدارة المخاطر التشغيلية، مبني وفقاً
لوثيقة المتطلبات (V2.0) ومخطط قاعدة البيانات `risks_ERD.mmd`، ويغطي مسارات
العمل الخمسة:

1. سجل المخاطر المحتملة (Potential Risk Register)
2. الحدث (Incident)
3. متابعة الحدث (Incident Follow-Up)
4. مؤشرات قياس المخاطر KRI (Indicator)
5. متابعة المؤشرات (Indicator Follow-Up)

الواجهة مبنية على قالب **NiceAdmin** (BootstrapMade) مُعاد بناؤه بالكامل
لدعم الاتجاه من اليمين لليسار (RTL) والخطوط العربية.

## ⚠️ ملاحظة مهمة حول بيئة الإنشاء

تم بناء هذا المشروع بالكامل (النماذج، الهجرات، المتحكمات، الواجهات) داخل بيئة
سحابية معزولة عن الإنترنت لا تسمح بالوصول إلى Packagist أو عميل Oracle
(OCI8 / Instant Client). لذلك:

- **لم يتم تشغيل `composer install` أو أي أمر `artisan` فعلياً** داخل بيئة
  الإنشاء. تم التحقق من صحة الشيفرة عبر `php -l` (فحص بنيوي) لكل ملف، ومراجعة
  يدوية دقيقة لكل مسار وعلاقة، لكن **يجب تشغيل الخطوات أدناه على جهازك/خادمك**
  للتأكد من عمل النظام فعلياً قبل الاعتماد عليه في الإنتاج.
- **Oracle** هو اتصال قاعدة البيانات الافتراضي (عبر حزمة
  `yajra/laravel-oci8`)، لكنه يتطلب تثبيت عميل Oracle (Instant Client) وتفعيل
  امتداد PHP الخاص به (`oci8` أو `pdo_oci`) على الخادم المستهدف. لتجربة سريعة
  بدون Oracle، استخدم اتصال `sqlite` (موضح أدناه).

## المتطلبات

- PHP 8.2 أو أحدث، مع تفعيل امتداد `ldap` (لتسجيل الدخول — راجع القسم أدناه)
- Composer 2
- قاعدة بيانات Oracle 12.2 أو أحدث (يفضَّل لدعم أسماء الجداول الطويلة/Extended
  Identifiers)، أو SQLite للتجربة السريعة
- عميل Oracle Instant Client + امتداد `oci8` (فقط في حالة استخدام Oracle)

## خطوات التثبيت

```bash
composer install

cp .env.example .env
php artisan key:generate

# اختر أحد الخيارين في .env:
# 1) Oracle (افتراضي):
#    DB_CONNECTION=oracle
#    DB_HOST=... DB_PORT=1521 DB_SERVICE_NAME=... DB_USERNAME=... DB_PASSWORD=...
# 2) SQLite (تجربة سريعة بدون Oracle):
#    DB_CONNECTION=sqlite
#    DB_DATABASE=/absolute/path/to/database/database.sqlite
#    (نفّذ: touch database/database.sqlite)

php artisan migrate
php artisan db:seed

php artisan serve
```

لا حاجة لتشغيل `npm install` أو أي خطوة بناء (build) — كل أصول القالب
(CSS/JS/Fonts) ملفات ثابتة داخل `public/assets` ويتم تحميلها مباشرة.

## تسجيل الدخول عبر LDAP (Active Directory)

تسجيل الدخول **لا يعتمد على كلمة مرور محلية مخزَّنة في قاعدة البيانات** —
بنفس أسلوب "نظام خدمة العملاء": يُبحث عن المستخدم محلياً بواسطة `userID` (اسم
مستخدم الدومين)، ثم تُتحقق كلمة المرور فعلياً عبر محاولة الربط (bind) بخوادم
LDAP الداخلية للجهاز، بالتتابع، حتى ينجح أحدها:

- الخوادم والإعدادات قابلة للتعديل من `.env` (`LDAP_HOSTS`, `LDAP_PORT`,
  `LDAP_DOMAIN_PREFIX`) — القيم الافتراضية مطابقة لنظام خدمة العملاء.
- **يتطلب تفعيل امتداد PHP `ldap`**: افتح `php.ini` (فى XAMPP عادة
  `C:\xampp\php\php.ini`)، احذف الـ `;` من بداية السطر
  `;extension=ldap` ليصبح `extension=ldap`، ثم أعد تشغيل Apache من لوحة
  تحكم XAMPP.
- **يعمل فقط عند الاتصال بالشبكة الداخلية للجهاز** (أو VPN) القادرة على
  الوصول لعناوين خوادم LDAP، وإلا سيفشل تسجيل الدخول حتى لو كانت بيانات
  المستخدم صحيحة.
- يجب أن يكون المستخدم موجوداً بالفعل في جدول `users` بنفس `userID` الخاص
  به على الدومين (يُضاف من شاشة "المستخدمون والصلاحيات")، وإلا ستظهر رسالة
  "المستخدم غير مسجل في النظام" حتى لو كانت بيانات الدخول على الدومين صحيحة.

بعد `db:seed` ستُنشأ حسابات تجريبية بأسماء مستخدمين وهمية (`admin`,
`risk.officer`, `risk.chief`, `it.officer`, `it.followup`, `it.kri`) — هذه
غير صالحة لتسجيل الدخول الفعلي عبر LDAP لأنها لا تطابق حسابات حقيقية على
الدومين. **يجب على مسئول النظام تعديل/إضافة المستخدمين الحقيقيين بأسماء
مستخدمين الدومين الصحيحة** من شاشة "المستخدمون والصلاحيات" قبل الاستخدام
الفعلي.

## البنية العامة

- `app/Models` — نماذج Eloquent مطابقة تماماً لجداول `risks_ERD.mmd` (مفاتيح
  UUID للجداول التشغيلية، ومفاتيح Int مخصصة لجدولي `sectors`/`departments`
  تمهيداً للربط المستقبلي بقاعدة بيانات نظام المشتريات PO).
- `app/Http/Controllers` — متحكم لكل مرحلة من مراحل العمل الخمس، بالإضافة
  إلى `Admin/*` لإدارة البيانات المرجعية والمستخدمين.
- `database/migrations` — هجرات مرتبة بحيث تُنشأ الجداول المرجعية أولاً ثم
  الجداول المعتمدة عليها، متوافقة مع Oracle 12.2+ (استخدم خيار
  `server_version` في `config/database.php` إذا كانت نسختك أقدم وتحتاج
  تقصير أسماء بعض الجداول/الأعمدة يدوياً).
- `database/seeders` — أدوار وصلاحيات (`spatie/laravel-permission`)، بيانات
  مرجعية (تصنيف بازل، حالات الحل والمتابعة، وحدات القياس...)، قطاعات/إدارات
  نموذجية، ومستخدمون تجريبيون.
- `resources/views` — كل الشاشات بالعربية RTL، مبنية على تخطيط موحّد
  `layouts/app.blade.php` (قالب NiceAdmin مُعاد بناؤه).

## الصلاحيات (الأدوار)

مبنية على مجموعات المستخدمين الواردة في وثيقة المتطلبات:

- `super-admin` — تحكم كامل (تجاوز تلقائي لكل الصلاحيات).
- `central-risk-officer` — تسجيل/تعديل المخاطر المحتملة والمؤشرات.
- `risk-chief` — اعتماد حالة الخطر وقرارات إغلاق متابعة الحدث.
- `sector-officer` — استعراض المخاطر والإجراءات المطلوبة فقط.
- `incident-officer` — تسجيل الأحداث التشغيلية.
- `sector-followup-officer` — تسجيل متابعات الأحداث المحوَّلة لقطاعه.
- `indicator-followup-officer` — تسجيل متابعات المؤشرات الدورية.

يمكن تعديل الأدوار والصلاحيات من `database/seeders/RolePermissionSeeder.php`
أو من شاشة "المستخدمون والصلاحيات" داخل النظام.

## الربط المستقبلي بنظام المشتريات (PO)

جدولا `sectors` و`departments` مصمَّمان ليُستبدل تعبئتهما لاحقاً بمزامنة تلقائية
من قاعدة بيانات نظام المشتريات (PO)، بدلاً من الإدخال اليدوي عبر شاشات الإدارة
الحالية — هذا الربط خارج نطاق وثيقة المتطلبات الحالية صراحةً.
